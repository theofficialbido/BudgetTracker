It's the user's daily 9pm expense check-in (Cairo time). The user also records expenses and income on the Budget Tracker phone app, which syncs into the Log sheet of Budget.xlsx (OneDrive/Documents/Budget folder on their computer, path C:\Users\Abdul\OneDrive\Documents\Budget\Budget.xlsx). The Log sheet is the single source of truth for both the phone app and this routine. Follow these steps in order.

1. READ FIRST. Stage a fresh copy of Budget.xlsx and read the Log sheet (rows 2 to 1000; columns Date, Category, Description, Amount (EGP); column F holds notes: never touch it). List the rows dated today. Log holds expenses only. Income lives on its own 'Income' sheet (Date in A, Source in B, Amount in C, rows 2 to 1000): read that sheet too and note today's income rows. Income is not spending: never ask about it as an expense and never count it as one.

2. ASK ONLY FOR WHAT IS MISSING. Send a short, friendly message: list today's expenses already logged (amount, category, description; these came from the phone app or an earlier entry) and mention any income logged today in one line. Then ask only: 'Anything else you spent today that isn't listed?'. Add one line: if they entered something on the phone that isn't listed, it hasn't synced yet (the phone must be on the home Wi-Fi with the laptop on; opening the app syncs it), so they can either sync and tell you to re-check, or just tell you about it. If nothing is logged yet today, ask for all of today's expenses (amount, category, and what it was). Don't edit anything yet.

3. IGNORE DUPLICATES. When they reply, decide which expenses are new. An expense is already logged if a row for that date has the same Category and the same Amount (the description wording may differ). Never add it again; tell them you skipped it as already logged. If they report the same category and amount N times, add only as many rows as needed to reach N rows for that date. If the amount matches an existing row but the category differs, ask one short question rather than guessing. Collapse exact repeats inside their own reply unless they clearly say it was bought twice. For an expense they say happened on another date, run the same check against that date.

4. WRITE. Add each new expense as a new row in the Log sheet only: put it in the first empty row among rows 2 to 1000, with the Date as an Excel date in column A (same format as the existing rows), Category in B (dropdown categories: Claude subscription, Breakfast, Going out, Other), Description in C, Amount in D. If they tell you about income, add it to the Income sheet instead (first empty row: Date in A, Source in B, Amount in C), and skip it if a row with the same date and amount is already there. Never put income in Log. Never change formulas, the Tracker or Plan sheets, existing rows, or column F of Log.

5. SAVE SAFELY. ALWAYS save back to that same file (stage it fresh first, then commit to the same path with the expectedMtimeMs guard); never create a new copy. The phone sync and OneDrive can write to the file at any moment, so if the commit is rejected because the file changed, stage it again, redo the duplicate check against the new contents, and retry (up to 3 times). If it still fails, say clearly that nothing was saved.

6. VERIFY AND SYNC. After saving, read the file back and confirm each new row is present exactly once. Confirm what you added and what you skipped as duplicates (for example 'added 2, skipped 1 already logged'). Tell them the new rows will appear in the phone app the next time it syncs (open the app or pull down to refresh on the home Wi-Fi), and that if they add a matching expense on the phone later (same date, category and amount) it will be recognised as the same one, not duplicated.

7. SUMMARY. Give a one-paragraph summary from the Tracker sheet: anything marked WATCH, OVER or UNPLANNED, days left in the month, and the 'Left after actual spending' figure. That figure is now this month's income actually received (the Income sheet) minus actual spending, so it can be negative early in the month before income is logged; say so if it is. If they have no new expenses, log nothing, say so, and still give the summary.
